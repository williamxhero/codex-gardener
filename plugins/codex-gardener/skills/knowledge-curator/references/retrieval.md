# Retrieval reference

`index.jsonl` is the authoritative promoted retrieval artifact. `retrieval.sqlite3` is a replaceable local derivative. Never hand-edit SQLite and never place prompt, transcript, tool output, query term, or secret data in either artifact.

Use `index-status` to observe derived-index health, `index-rebuild` to rebuild it from JSONL, and read-only `index-audit` to review stale entries (90 days plus 50 misses), normalized-summary duplicates, superseded entries, orphaned targets, and invalid metadata. A bad or locked derived index fails open; repair it explicitly rather than inventing a JSON fallback.

At promotion, supply only narrow approved metadata: lowercase task types/languages/tools/platforms, relative path globs, normalized negative phrases, a bounded minimum score, and repeatable superseded fingerprints. Scope, negative, and path metadata filter; other matching metadata boosts. `estimated_tokens` is computed from the final rendered injection line and is never curator input. Audits only report. To disable active retrieval, record an explicit `retired` resolution with `stale`, `duplicate`, or `superseded` reason; never auto-retire.

Rebuild writers and usage updates share a bounded per-store lock. A rebuild keeps the old healthy database until its replacement passes validation. If a lookup cannot obtain that writer lock for its usage bookkeeping window, only that counter update is skipped; retrieval results remain available. SessionStart attempts repair only for a small authoritative index within its fixed budget. Large, locked, corrupt, or slow stores wait for explicit `index-rebuild`; old healthy databases remain untouched. The local learning `.gitignore` excludes the derived SQLite database, its sidecars, rebuild temporaries, and deferred maintenance/audit/capture data; only authoritative reviewed records may be promoted.

Pending maintenance is deliberately separate from retrieval. New pending records require a currently readable trusted transcript and keep only a private path plus a bounded safe capsule; `maintenance-status` exposes aggregate evidence health and targeted legacy metadata, never capsule contents. Legacy records without a capsule remain compatible. Use `pending-prune-unreviewable --confirm` only for explicit terminal cleanup of active evidence that has become unavailable; it does not create or change candidate or promoted knowledge.
